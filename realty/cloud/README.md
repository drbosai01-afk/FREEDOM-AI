# FREEDOM REALTY — этап 2: облачная база и авторизация

Это серверная основа Блокнота, **не публично развернутый сервис**.

## Возможности
- Регистрация и вход по email и паролю (Argon2), 12-часовой JWT.
- SQLAlchemy + SQLite локально или PostgreSQL через DATABASE_URL в продакшене.
- Объекты, клиенты и показы сохраняются на сервере, изолированы по аккаунтам.
- Синхронизация при открытии/обновлении списка с другого устройства через один сервер и аккаунт.
- Контроль версий для предотвращения незаметной перезаписи при конкурентном редактировании.

## Быстрый локальный запуск
```bash
cd realty/cloud
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
export JWT_SECRET="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
uvicorn main:app --host 127.0.0.1 --port 8000
# открыть http://127.0.0.1:8000
pytest -q
```

Windows: активация .venv/Scripts/activate, переменные окружения по синтаксису вашей оболочки.

## Ограничения
Предыдущий локальный HTML и этот новый облачный интерфейс сейчас отдельны: автоматический импорт существующей базы не реализован. Прайсы и данные каталога ещё не перенесены. API намеренно не хранит контакты, полученные без законного основания. В текущей реализации нет общего каталога между разными пользователями.


## Импорт наполненного каталога (этап 3)

- После запуска сервера и регистрации откройте главную страницу, выберите JSON-файл `Каталог_Краснодар_105_для_импорта.json` и нажмите **Импортировать без перезаписи**.
- Импорт выполняется только с авторизацией, в базу конкретного пользователя; до 300 записей за запрос.
- Записи с повторяющимися `record_id` пропускаются без изменения старых данных. При неверной записи весь текущий пакет отклоняется.
- Исторический каталог 01.11.2026 содержит 105 объектов. Цены/наличие могут устареть: импорт не означает обновление из Google Sheets.
- Исходный Excel содержит конфиденциальные коды доступа к квартирам — **не выкладывайте его и импортный JSON в публичный GitHub**. Экспортируемый для этого этапа JSON намеренно исключает коды.
- Сам сервер пока не развернут в интернете. Автоматические тесты проверяют API, не реальную синхронизацию между телефонами.


## Полный архив без изменения данных (разработка)

Облачная версия добавляет раздел «Полная резервная копия исходного Блокнота». Загрузка авторизована и отправляет исходный JSON частями по 128 КиБ, до 25 МиБ. Сервер сверяет размер и SHA-256 и возвращает проверенную копию без изменения таблицы объектов. Потребуется постоянная PostgreSQL: SQLite в эфемерной среде Vercel не гарантирует сохранность файлов. До подключения постоянной базы и HTTPS загружать реальные клиентские данные нельзя.

**Важно:** это механизм резервного копирования, а не миграция существующей локальной базы. Он не умеет читать IndexedDB/LocalStorage другого домена. Текущий адрес `bloknot-rieltora-krasnodar.vercel.app` не переподключён и сохранён без изменений. Исходные объекты, статусы, фото и персональные данные останутся в текущем Блокноте до проверки полного архива. Для реальной миграции: проверить количество объектов, количество на разборе, дубли, ссылки и схемы данных; создать отдельную точку восстановления; только затем перенести и протестировать две сессии.

## Этап синхронизации: полный Блокнот

Исходная работающая версия хранит `state` в IndexedDB `krasnodar-notebook` / `store` / `state`, с резервным fallback `localStorage['realtor-state']`. Именно его читает `cloud-sync-addon.js`, а не отдельный упрощённый каталог.

API:
- `GET /api/sync/state` — прочитать свою облачную базу или `version:0`, если она ещё не создана;
- `PUT /api/sync/state` — сохранить всю структуру с `expected_version`, включая фотографии и дополнительные поля;
- `GET /api/sync/history` и `GET /api/sync/history/{version}` — читать историю предыдущих состояний.
- При конфликте версий API возвращает 409, а не перезаписывает данные.
- При падении числа записей более чем на 10% API по умолчанию блокирует запись.
- Перед восстановлением из облака клиент делает локальную копию в той же транзакции IndexedDB и требует отдельного подтверждения.

Для запуска на реальных телефонах НЕОБХОДИМЫ: постоянная PostgreSQL (не sqlite в serverless), защищённый `JWT_SECRET`, HTTPS, ограничение запросов, резервирование самой PostgreSQL, контроль CORS и согласия на обработку персональных данных. После этого — интеграция `cloud-sync-addon.js` на тот же origin, что и API, и тест двух Android-устройств. Нельзя автоматически включать эту версию на текущем сайте.

Временная проверочная сборка Vercel `freedom-realty-api-ci` — **только для тестов**, она не является постоянной базой и не должна использоваться для настоящих клиентских данных.

Тесты при изолированном запуске 13.11.2026: 8 passed, 1 warning (включая проверку синтетических 1161 объектов, 532 очереди и 96 источников). Это проверка API и целостности данных, не подтверждение браузерной синхронизации на двух телефонах.
